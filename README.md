# RSS-читалка

Локальный веб-сервер: слева дерево подписок, справа список статей. Один процесс Node.js,
**без npm-зависимостей** — свой разбор XML, RSS 2.0 / RSS 1.0 (RDF) / Atom, OPML,
каналы Telegram и протокол Fever API для внешних клиентов.

```
rss-reader/
├── server.mjs            вход, пользователи, админка /admin, общий HTTP-порт
├── reader-core.mjs       сама читалка: поднимается по экземпляру на пользователя
├── lib/xml.mjs           XML-парсер (CDATA, сущности, пространства имён)
├── lib/feed.mjs          RSS/Atom → статьи, определение фида по HTML-странице
├── lib/readability.mjs   вытаскивание основного текста статьи со страницы
├── lib/telegram.mjs      каналы Telegram: веб-превью t.me и Bot API
├── lib/fever.mjs         протокол Fever API для внешних клиентов
├── lib/auth.mjs          пароли (scrypt), сессии в cookie, ключ Fever
├── lib/users.mjs         список пользователей, роли, ключи (data/users.json)
├── lib/store.mjs         хранилище: state.json + content/<лента>.json
├── public/               интерфейс (index.html, app.js) и админка (admin.html, admin.js)
├── data/                 users.json и папки пользователей u/<id>/ (создаётся само)
├── deploy/               установка: install-vps.sh (VPS + HTTPS + HAProxy), install.sh, systemd, пример nginx
└── start.cmd / start.sh  запуск вручную (Windows / Linux)
```

## Запуск

```bash
node server.mjs                    # http://127.0.0.1:8787
node server.mjs --port 9000        # другой порт
node server.mjs --host 0.0.0.0     # доступ из локальной сети
node server.mjs --refresh 5        # обновлять ленты раз в 5 минут
node server.mjs --data /srv/rss    # каталог данных
```

## Интерфейс

* **Две панели.** Слева подписки (с папками и счётчиками непрочитанного), справа — статьи.
* **Где что настраивается.** Настройки вида (тема, гамма, фон, шрифты, ширина текста, рамки,
  условия прочтения, выбранный раздел и фильтр «непрочит.») хранятся в браузере, поэтому у каждого
  устройства они свои. Настройки учётной записи (интервал обновления, автодокачка, токен бота,
  режим показа и число строк у конкретной ленты, порядок статей) хранятся на сервере и общие для
  всех устройств этого пользователя.
* **Значения по умолчанию для нового клиента.** Новый браузер или новая учётная запись
  начинают с таких настроек (уже существующие ничего не теряют — у них свои сохранённые значения):

  | Настройка | Значение по умолчанию |
  |---|---|
  | Тема, гамма | тёмная, «Графит» |
  | Режим показа / строк | «Кратко», 4 строки |
  | Порядок статей | дата по убыванию |
  | Фильтр | только непрочитанные |
  | Отметка о прочтении | при раскрытии и при прокрутке (по рамке) |
  | Ширина текста | 100 % |
  | Интервал обновления | 5 минут |
  | Докачка полного текста | включена |

  Изменить умолчания можно в коде: клиентские — в `public/app.js` (объект `prefs` и `settings`),
  серверные — в `reader-core.mjs` (`REFRESH_MINUTES`, `defaultLines`) и в `/etc/rss-reader.env`.
* **Фильтры лент.** Поиск ищет по заголовку, описанию, названию ленты и категориям. Если
  запрос найден, под строкой поиска появляются две кнопки: **«Скрывать такие статьи»** и
  **«Показывать только такие»** — они сохраняют фильтр **для текущей ленты** (в общих видах
  вроде «Непрочитанных» кнопки недоступны, там видна подсказка). Фильтр — это слово или фраза:
  «скрывать» убирает подходящие статьи из списка, «только» оставляет лишь их; фильтров у ленты
  может быть несколько. Кнопка **«Фильтры (N)»** открывает окно со всеми фильтрами всех лент —
  там их можно изменить (слово и режим) или удалить. Скрытые фильтром статьи не считаются
  прочитанными и возвращаются, если фильтр удалить.
* **Раскрытие на месте.** Статья раскрывается прямо в списке. Если полного текста нет —
  он докачивается по клику; дальше хранится, пока вы её не прочитаете.
  В правом верхнем углу карточки — три кнопки: «в избранное» (☆), «прочитано» (✓) и
  «поделиться» (⇪: на телефоне открывается системное окно, на компьютере ссылка копируется
  в буфер обмена). У раскрытой статьи они **остаются на виду** при прокрутке: прилипают к верху
  окна чтения и уезжают вместе с карточкой, когда дочитываете до её конца.
* **Режим показа для каждого канала.** Переключатель «Кратко / Полностью» вверху списка
  запоминается отдельно для каждого канала; для остальных видов (папка, Избранное)
  он задаёт режим по умолчанию. «Кратко» — строка с ведущей картинкой, «Полностью» —
  развёрнутый текст.
* **Темы.** Кнопка ◐ переключает тёмную → светлую → «как в системе»; та же настройка в ⚙.
  Ссылку можно открыть сразу в нужной теме: `http://127.0.0.1:8787/?theme=light`.
* **Живое обновление.** Страница держит открытым поток `/api/events` и получает пинг, когда
  данные изменились: статью отметил прочитанной клиент Fever на телефоне — в браузере она
  станет прочитанной сразу, без обновления страницы. Если поток недоступен (например, его
  закрывает прокси), остаётся обычный опрос раз в две минуты.
* **Клавиатура.** `j`/`k` (или `↓`/`↑`) — по списку, `пробел` — раскрыть статью,
  `m` — прочитано/непрочитано, `s` — в избранное, `o` — открыть оригинал,
  `u` — только непрочитанные, `r` — обновить, `/` — поиск, `Esc` — сбросить.
* **Комментарии.** У статей Хабра в конце есть кнопка «Показать комментарии»: сервер берёт
  ветки из JSON-API сайта, показывает авторов, оценки и ответы (кэш — 30 минут, есть кнопка
  обновления). Так же работают **комментарии Mobile-Review**: сайт на WordPress, поэтому сервер
  находит статью через открытый REST API (`/all/wp-json/wp/v2/posts?slug=…`), а затем забирает
  комментарии по её номеру. Для сайтов без открытого API кнопка не показывается.
  Ветки комментариев кэшируются **на сервере** — в той же записи, что и текст статьи
  (`data/u/<id>/content/<лента>.json`), поэтому удаляются вместе с ней по сроку хранения.
  Свежесть — 30 минут (`COMMENTS_TTL_MINUTES`), дальше при открытии они запрашиваются заново;
  кнопка «Обновить» в блоке сбрасывает кэш принудительно. В браузер комментарии не
  складываются в кэш — приходят по запросу и живут только в памяти вкладки.
  Пределы: Хабр — до 200 комментариев на статью, Mobile-Review — до 100.
  Число комментариев берётся из самой ленты (`<slash:comments>` у WordPress) — тогда оно видно
  сразу при обновлении, без запроса к сайту; если лента его не сообщает, счётчик запоминается
  после первого открытия комментариев.
* **«Только картинки» для ленты.** У фото-лент (например «Смешные прикольные картинки») в статье
  полезна только картинка, а разметка сайта мешает. В панели инструментов есть переключатель
  **«только картинки»** — он сохраняется для конкретной ленты: в раскрытой статье остаются лишь
  сами изображения (в порядке текста, без подписей и блоков сайта).
* **Видео из постов Telegram.** У поста с видео есть кнопка «▶ Просмотреть видео»: она
  подставляет плеер, который тянет файл через `/api/video` — потоком, без кеша на диске,
  с поддержкой перемотки (`Range`). Не открылось — вместо плеера сообщение и ссылка на пост.
  Кнопка появляется и у постов, где есть и текст, и видео: ссылка ищется в `<video src>`,
  `<source>`, data-атрибутах плеера и просто в разметке поста (репосты).
* **Настройки вида.** Тема, **шрифт интерфейса** (восемь наборов), **межстрочный интервал**
  (маленький / нормальный / большой), размеры шрифтов дерева, статьи и краткого вида, плотность
  списка, картинки и рамки в списке, режим показа по умолчанию.
  Размер «шрифт в дереве» задаёт и общий масштаб интерфейса: 13 px — обычный вид, 12 px —
  компактнее, 20 px — крупнее. Заголовок статьи чуть меньше её текста (0,95 от размера).
* **Шрифты интерфейса.** Восемь наборов: системный, узкий (condensed), книжный с засечками,
  моноширинный, рукописный, а также плотный, широкий и заголовочный (они отличаются
  межбуквенным расстоянием). Набор применяется ко всему интерфейсу и к статьям.
  Узкий шрифт **встроен в читалку** (PT Sans Narrow, файлы в `public/fonts/`) — иначе на Android
  он подменялся бы обычным Roboto: система не отдаёт своё узкое начертание по CSS-имени.
  Шрифт распространяется по лицензии SIL Open Font License 1.1 (свободно использовать и
  распространять вместе с приложением).
* **Когда считать прочитанным.** В настройках (⚙ → «Когда считать прочитанным») выбирается один
  из трёх вариантов: **по клику**, **при прокрутке** или **по клику и при прокрутке**.
  Статья считается прочитанной по двум правилам:
  1. её верх ушёл под шапку — под липкую полосу с датой («СЕГОДНЯ» и т. п.);
  2. на неё перешла рамка **при прокрутке** пользователя (после входа в ленту или кнопки
     «Следующая» рамка стоит на статье, но прочитанной её не делает).

  Высота шапки измеряется на лету, поэтому правило одинаково работает на телефоне и на мониторе.
* **Кнопки «Предыдущая» и «Следующая»** просто прокручивают список к соседней статье: текущая
  не закрывается, следующая не раскрывается. Прокрутка учитывает липкую полосу с датой, поэтому
  заголовок не уезжает под неё. Для длинной статьи считается только «есть куда идти».
* **Мобильный вид.** На экранах до 900 px — одна панель: список статей на весь экран, а дерево
  подписок уезжает в выдвижную панель. Открывается кнопкой ☰ или **свайпом вправо с левой
  половины экрана**; закрывается свайпом влево, нажатием по затемнению или при выборе ленты.
  Свайп **справа налево по правой половине экрана** переходит к следующей статье — то же, что
  кнопка «Следующая».
  Кнопки увеличены под палец (не меньше 36 px), перетаскивание подписок на телефоне отключено.
  Шапка занимает две строки: название со значками и сводка, остальное — под кнопкой «⋯».
* **Приложение на домашний экран (PWA).** Читалку можно поставить как приложение: она
  открывается без адресной строки, со своей иконкой, и показывает оболочку даже без сети
  (статьи, разумеется, приходят с сервера). Нужен HTTPS — на этом сервере он есть.

  * **Android (Chrome):** меню браузера → «Установить приложение», либо кнопка
    «📱 Установить приложение» в шапке (она появляется, когда браузер готов к установке).
  * **iPhone/iPad (Safari):** «Поделиться» → «На экран „Домой“». Кнопка в шапке в этом случае
    просто напоминает, что делать.

  Состав: `public/manifest.webmanifest` (имя, цвета, иконки), `public/sw.js` (сервис-воркер:
  сначала сеть, при её отсутствии — кэш; запросы к `/api`, `/fever`, `/admin` не кэшируются),
  иконки `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`.
  Иконки рисуются скриптом `tools/make-icons.mjs` (`node tools/make-icons.mjs`) — без внешних
  библиотек, поэтому их легко перерисовать под другой цвет или значок.
* **Фильтр дерева.** Можно показывать все подписки или только те, где есть непрочитанное.
* **Счётчики в дереве.** У каждой ленты — число непрочитанных, а в скобках `(+N)` — сколько
  статей пришло **в последнюю синхронизацию** (сервер отдаёт это полем `addedByFeed`).
  Счётчики считаются без учёта статей, скрытых фильтрами ленты. Кнопки «✎» и «×» появляются
  при наведении слева от счётчика и не сдвигают его.
* **Длинный заголовок и картинка.** На экранах до 560 px картинка в карточке стала обтекаемой:
  заголовок и подпись идут рядом с ней и продолжаются под ней, а не сжимаются в узкую колонку.
* **Новые статьи не вклиниваются.** Пока вы находитесь в ленте, список не меняется: новые статьи
  ждут и появляются при переходе в другой раздел или по полоске «Новых статей: N — Показать».
  Удержание действует только в этом браузере, другие устройства получают новинки сразу.
* **«Избранное».** Галочка «непрочит.» в этом разделе скрыта и не действует — показываются все
  избранные статьи; на другие разделы переход в «Избранное» не влияет.
* **Вход.** Пока вы не вошли, интерфейс читалки скрыт — видно только окно входа. Неверный или
  пустой логин даёт понятное сообщение («неверный логин или пароль», «Введите логин» и т. п.),
  без мелькания читалки и без приветственного тоста.
* **Ширина текста статьи** меняется кнопками «−» и «+» рядом с переключателем «Кратко/Полностью»:
  от 100 % ширины окна (по умолчанию, как раньше) до 50 %. Сужается вся карточка — и текст,
  и заголовок, — а на узких значениях она встаёт по центру, так что поля появляются с обеих сторон.
  Значение **своё на каждом устройстве** (как тема): на телефоне удобно уже, на большом экране шире.
  Пока на устройстве ничего не выбрано, берётся значение из настроек учётной записи.
* **Рамки в интерфейсе** можно отключить (⚙ → «Вид»): у карточек, панелей, кнопок и полей ввода
  рамки исчезают, пропадает и граница между деревом и списком. Остаётся только тонкая рамка цвета
  темы у активной статьи — той, что читается сейчас или вот-вот станет прочитанной при прокрутке.
* **Фон читалки** (⚙ → «Вид») выбирается отдельно от гаммы: «фон темы» — чистый белый
  в светлой теме и чистый чёрный в тёмной, «фон с гаммой» — цвет выбранной ниже гаммы
  (по умолчанию). Сама гамма при этом задаёт панели, границы и акцентный цвет.
  Гамм по девять на каждую тему: у тёмной — «Графит», «Синяя», «Изумруд», «Фиалка», «Янтарь»,
  «Лазурь», «Роза», «Лес», «Монохром»; у светлой — «Дневная», «Небо», «Мята», «Лаванда»,
  «Песок», «Лёд», «Румянец», «Сепия», «Монохром». «Монохром» — серая гамма без цветного
  акцента: и в тёмной, и в светлой теме всё построено на оттенках серого.
* **Интервал обновления** задаётся в настройках (по умолчанию 10 минут, минимум 5) и применяется
  сразу, без перезапуска сервера. У каждого пользователя своё расписание: таймеры запускаются
  при старте сервера для **всех** аккаунтов, а не только для того, кто открыл читалку, и сдвинуты
  друг относительно друга, чтобы обновления не били в одну секунду.

## Пользователи и админка

Читалка многопользовательская: у каждого свой логин, свои подписки, папки, статьи, отметки
о прочтении, настройки и ключ Fever. Данные лежат раздельно:

```
data/
├── users.json          логины, роли, scrypt-хеши паролей, ключи Fever
└── u/<id>/             папка пользователя
    ├── state.json      его подписки, папки, статьи и настройки
    ├── content/        сохранённые тексты статей
    └── media/          картинки Telegram и иконки подписок
```

Первый администратор создаётся при первом запуске: логин `admin`, пароль `admin`
(меняется переменными `ADMIN_USER`/`ADMIN_PASS` в окружении). Дальше всё делается в админке
**`http://<хост>:8787/admin`**:

* создать пользователя (логин, пароль, роль — пользователь или администратор);
* сменить пароль, переименовать логин, выдать или снять права администратора;
* отключить пользователя или удалить его вместе с подписками и статьями;
* посмотреть и перевыпустить ключ Fever, увидеть число подписок, статей и непрочитанных.

Себя удалить нельзя, как и снять права с последнего администратора. Если данные прежней
одно-пользовательской версии (`data/state.json`, `content/`, `media/`) ещё на месте, при первом
запуске они автоматически переезжают в папку администратора — подписки не теряются.

Свою учётную запись можно посмотреть в ⚙ → «Аккаунт и Fever API»: там же смена пароля
и ссылка на админку для администраторов.

## Доступ и Fever API

1. **Вход в веб-клиент.** Логин и пароль — учётная запись из админки. Пароль хранится как
   scrypt-хеш; вход запоминается cookie на 30 дней (галочка «запомнить меня»).
2. **Внешние клиенты по протоколу Fever** (Reeder, Unread, Fiery Feeds, NetNewsWire и другие).
   В клиенте укажите адрес `http://<хост>:8787/fever/`, логин и пароль своей учётной записи;
   если клиент просит отдельный `api_key` — он показан в админке и в настройках читалки.
   Ключ считается как md5 от «логин:пароль» и меняется вместе с паролем (в админке можно
   выпустить и произвольный новый ключ).

Каждый клиент видит только подписки своего пользователя: отметки о прочтении, избранное
и списки лент у разных аккаунтов не пересекаются.

Поддержаны запросы: `api=feeds`, `groups`, `favicons`, `items` (с `since_id`, `max_id`,
`with_ids`), `unread_item_ids`, `saved_item_ids`, `links`, а также запись: `mark`
(item/feed/group, `as=read/unread/saved/unsaved`) и `save`. Папки читалки отдаются как группы
Fever, ленты и статьи получают числовые идентификаторы, которых требует протокол.

Особенности, важные для мобильных клиентов:

* **Статьи отдаются порциями по 50** — как и требует протокол. Клиент запрашивает следующие
  через `since_id` (id последней полученной статьи) и предыдущие через `max_id`. Отдать всю
  библиотеку разом нельзя: телефон на этом падает.
* **Ответ принимается и в корне сайта.** Настоящий Fever отвечает по адресу `…/fever/?api`,
  но некоторые клиенты настроены просто на домен и стучатся в `/` — читалка понимает и такой
  запрос (определяет по аргументам `api`, `feeds`, `items` и ключу), а не отдаёт страницу.
* **Неверный или отсутствующий ключ** — ответ `{"api_version":3,"auth":0}` с кодом 200,
  как в протоколе. Клиент показывает ошибку входа вместо разбора HTML.
* В каждом успешном ответе есть `last_refreshed_on_time` — время последнего обновления лент.

## Докачка полного текста

Многие ленты отдают только анонс. Для таких статей читалка скачивает страницу и вытаскивает
основной текст (`lib/readability.mjs`), сохраняя его до прочтения:

* автоматически — в фоне, для непрочитанных статей, у которых текст ленты короче ~900 знаков;
* по требованию — кнопкой ⤓ в статье или просто раскрытием статьи, если текста ещё нет;
* очередь продолжает работу сама (раньше она останавливалась, отсюда было «застыла»);
  её состояние видно в ⚙, там же можно запустить или очистить очередь и выключить автодокачку.

## Каналы Telegram

Работают двумя способами.

1. **Публичные каналы — через веб-превью** `t.me/s/<канал>`, без всякой настройки.
   Читалка забирает не только последние ~20 постов, но и историю (несколько страниц),
   вместе с фотографиями и ссылками на видео. Подписка вида `https://t.me/канал`
   добавляется как обычная лента.
2. **Через бота — для каналов, где бот администратор.** Создайте бота у @BotFather,
   вставьте токен в ⚙ → «Каналы Telegram», добавьте бота администратором в свои каналы —
   новые посты будут появляться сразу (сервер опрашивает `getUpdates`). Картинки постов
   бот отдаёт через `/api/media`, они кэшируются в `data/media`.

Важное ограничение Telegram: **бот не может читать чужие публичные каналы** — только те,
куда его добавили администратором. Для произвольных чужих каналов остаётся веб-превью;
если нужна полная история и мгновенная доставка по любым каналам, понадобится режим
пользовательского клиента (MTProto, api_id/api_hash и вход по номеру телефона) — это
отдельная доработка с внешней библиотекой.

## Скорость: сжатие и кэш ответа

`/api/data` отдаёт всё состояние читалки одним JSON — на 1700 статей это около 2 МБ
(примерно 1 КБ на статью). Чтобы не собирать и не гонять это на каждый запрос:

* **ответ сжимается** (brotli или gzip, что поддерживает браузер) — 2,2 МБ превращаются
  в ~650 КБ gzip или ~550 КБ brotli;
* **тело кэшируется по ревизии**: пока данные не менялись, отдаётся готовый буфер (около 10 мс),
  сериализация выполняется один раз;
* параллельные запросы на одну ревизию ждут одну сборку, а не собирают каждый своё;
* поддержан `ETag` — если браузер уже видел эту ревизию, приходит пустой `304`;
* статические файлы (`html/css/js/webmanifest`) сжимаются один раз и кэшируются по времени
  изменения; шрифты отдаются с типом `font/woff2`.

## Хранение

```
data/users.json                логины, роли, scrypt-хеши паролей, ключи Fever
data/u/<id>/state.json         подписки, папки, метаданные статей, прочитано/избранное, настройки
data/u/<id>/content/<лента>.json  тела статей (текст ленты и докачанный)
data/u/<id>/media/             картинки постов Telegram и иконки подписок
public/fonts/                  встроенный узкий шрифт (PT Sans Narrow, woff2)
```

Непрочитанные статьи не удаляются (жёсткий предел — 1500 на ленту), избранное хранится всегда,
прочитанное живёт 30 дней. Запись атомарная, с повторами на случай блокировки файла
синхронизацией (ownCloud, антивирус).

### Сколько что занимает и когда чистится

| Что | Срок | Настройка |
|---|---|---|
| Непрочитанные статьи | не удаляются (до 1500 на ленту) | `MAX_UNREAD_PER_FEED` |
| **Прочитанные статьи** | **30 дней с момента прочтения**, затем удаляются вместе с текстом и картинками | `KEEP_READ_DAYS` |
| Прочитанные сверх лимита | хранится 1000 последних на ленту | `MAX_READ_PER_FEED` |
| Избранное | всегда | — |
| Картинки постов Telegram и кэш миниатюр | удаляются вместе со своей статьёй | — |

Срок считается **от момента прочтения**, а не от даты публикации: старую статью, прочитанную
сегодня, читалка держит ещё 30 дней. Чистка запускается, когда вы отмечаете статьи прочитанными,
при обновлении ленты и раз в сутки по всем лентам сразу — чтобы ленты, которые давно не
обновлялись, не копили старьё.

### Картинки в списке

Ведущие картинки статей лежат на чужих сайтах, поэтому в списке они грузились каждый раз заново
с внешних серверов (и это заметно медленнее, чем всё остальное). Теперь читалка скачивает их
один раз, кладёт в свой каталог медиа и отдаёт со своего домена: повторные заходы в ленту
показывают картинки мгновенно, а браузер держит их в кэше неделю. Если скачать не удалось
(картинка недоступна, слишком большая или это не изображение) — браузеру отдаётся исходный
адрес, то есть картинка всё равно покажется, просто без кэша.

**Картинки с http-сайтов** (например `batona.net`) браузер на странице по https блокирует как
«смешанное содержимое» — они не показывались вовсе. Теперь такие картинки в тексте статьи идут
через свой прокси `/api/img?u=…`: сервер скачивает их сам, кэширует и отдаёт по https. Ссылки
при этом не переписываются, а запросы внутрь локальной сети прокси отклоняет (403).

### Кодировка текстовых файлов (важно при правках)

Все текстовые файлы читалки — **UTF-8 без BOM**. При правках нельзя гонять их через
`Set-Content`/`Out-File` в PowerShell: файл читается как ANSI, кириллица и значки (⟳, ⋯, ☰)
превращаются в «РћР±РЅРѕРІРёС‚СЊ» и обратно уже не собираются. Правьте файлы редактором,
который пишет UTF-8, либо в PowerShell так:

```powershell
$p = 'public/index.html'
$t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
$t = $t -replace 'старое', 'новое'
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))   # $false — без BOM
```

Если файл всё-таки испортили, поможет `node tools/fix-encoding.mjs <файл> <куда>`: он разворачивает
двойное перекодирование (UTF-8 → CP1251 → UTF-8) и сообщает, сколько символов потеряно. Симптомы:
в интерфейсе вместо русских букв «Р РѕРІР°СЏ», вместо значков — «в‹Ї» и «рџ“±».

## Установка на VPS (Ubuntu/Debian) — одной командой

Скрипт `deploy/install-vps.sh` ставит всё сам: Node.js, службу, HTTPS с сертификатом
Let's Encrypt и маршруты в HAProxy, если он на сервере уже есть.

```bash
# скопируйте каталог rss-reader на сервер, например:
#   pscp -r rss-reader root@<сервер>:/tmp/
ssh root@<сервер>
cd /tmp/rss-reader
sudo DOMAIN=rss.example.com EMAIL=you@example.com ./deploy/install-vps.sh
```

Что должно быть готово **до** запуска:

| Требование | Зачем |
|---|---|
| Ubuntu 20.04+ или Debian 11+, systemd | служба и таймеры |
| root (sudo) | установка пакетов и правка HAProxy |
| A-запись домена на IP сервера | Let's Encrypt проверяет домен по http |
| Свободные порты 8787 (http) и 8788 (https) на 127.0.0.1 | сама читалка |
| `curl`, `xz-utils` | скрипт доставит сам, если их нет |
| HAProxy (необязательно) | если есть — маршруты добавятся автоматически |

Node.js, certbot и всё остальное скрипт ставит сам (Node — официальной сборкой в `/opt`,
без добавления apt-репозиториев).

### Что именно делает скрипт

1. **Node.js 22** — качает официальную сборку в `/opt/node-v22.11.0-linux-x64`,
   делает ссылку `/usr/local/bin/node`. Если Node ≥ 18 уже установлен — не трогает.
2. **Пользователь и каталоги** — системный пользователь `rss` (без входа в оболочку),
   данные в `/var/lib/rss-reader`, каталог проверок Let's Encrypt `/var/www/acme`,
   каталог сертификата `/etc/rss-reader/tls`.
3. **Код** — копирует `server.mjs`, `reader-core.mjs`, `lib/`, `public/`, `deploy/`
   в `/opt/rss-reader` (владелец root, запись только у root).
4. **Настройки** — `/etc/rss-reader.env` (права 600): порты, пути, логин и пароль
   первого администратора (по умолчанию `admin` / `admin`).
5. **Служба systemd** `rss-reader`: запуск от пользователя `rss` с ограничениями
   (`ProtectSystem=strict`, запись только в каталог данных), автозапуск при загрузке.
6. **HAProxy** — добавляет в существующий конфиг две строки маршрутизации и два бэкенда:
   ```haproxy
   # во frontend на :80
   use_backend rss_reader_http if { req.hdr(host) -i rss.example.com }
   # в listen на :443 (режим tcp, выбор по SNI)
   use_backend rss_reader_tls if { req.ssl_sni -i rss.example.com }

   backend rss_reader_http
     mode http
     server srv 127.0.0.1:8787
   backend rss_reader_tls
     mode tcp
     server srv 127.0.0.1:8788
   ```
   Перед правкой делается копия `haproxy.cfg.bak.<дата>`, новый конфиг проверяется
   `haproxy -c`, и только потом идёт `systemctl reload haproxy`. Если проверка не прошла —
   старый файл остаётся нетронутым.
7. **Сертификат Let's Encrypt** — ставит certbot и получает сертификат через проверку
   `http-01` в режиме webroot: файл проверки отдаёт сама читалка (по http, без входа),
   а HAProxy направляет домен на неё.
8. **Обработчик сертификата** `/usr/local/bin/rss-reader-tls.sh` — копирует свежий
   сертификат в `/etc/rss-reader/tls` (владелец `root:rss`, права 640) и перезапускает
   службу. Он же прописан как deploy-hook в certbot, поэтому продление сразу доходит
   до читалки.
9. **Cron** `/etc/cron.d/rss-reader-cert` — продление дважды в день:
   ```
   23 3,15 * * * root certbot renew --quiet --deploy-hook /usr/local/bin/rss-reader-tls.sh
   ```
   (certbot renew сам решает, нужно ли продление: обычно раз в 60 дней.)

### Параметры запуска

```bash
DOMAIN=rss.example.com      # домен (по умолчанию rss.letsplay.today)
EMAIL=you@example.com       # почта для Let's Encrypt; без неё — регистрация без почты
APP_DIR=/opt/rss-reader     # куда положить код
DATA_DIR=/var/lib/rss-reader # где хранить данные
HTTP_PORT=8787              # локальный http
HTTPS_PORT=8788             # локальный https (наружу его не открывайте)
WITH_HAPROXY=no             # не трогать HAProxy (например, если стоит nginx)
SKIP_NODE=yes               # не проверять и не ставить Node.js
SKIP_CERT=yes               # не получать сертификат
ADMIN_USER=admin ADMIN_PASS=<пароль>  # первый администратор
```

### Проверка после установки

```bash
systemctl status rss-reader            # служба активна
curl -I http://rss.example.com/        # 301 на https
curl -I https://rss.example.com/       # 200
journalctl -u rss-reader -f            # логи читалки
certbot certificates                   # срок действия сертификата
certbot renew --dry-run                # проверка продления (без реальных изменений)
```

Читалка откроется по адресу `https://<домен>/`, админка — `https://<домен>/admin`.
Первый вход — логин и пароль из `/etc/rss-reader.env`, сразу смените пароль в админке.
Внешние клиенты (Fever) подключаются к `https://<домен>/fever/` под своим аккаунтом.

### Обновление кода

```bash
# заново скопируйте каталог на сервер и выполните
sudo /opt/rss-reader/deploy/install-vps.sh
```

Скрипт идемпотентен: код обновляется, данные, сертификат, настройки и маршруты HAProxy
не дублируются и не перезаписываются.

### Если что-то не так

| Симптом | Причина и лечение |
|---|---|
| `http://<домен>` отдаёт чужой сайт | домен не попал в правила HAProxy: проверьте `grep rss_reader /etc/haproxy/haproxy.cfg` |
| сертификат не выдаётся, ошибка `404` на `/.well-known/acme-challenge/` | читалка не отдаёт проверку: `curl http://<домен>/.well-known/acme-challenge/test` должен вернуть 404 от читалки, а не чужую страницу; проверьте `ACME_DIR` в `/etc/rss-reader.env` и права на `/var/www/acme` |
| браузер не пускает, «слишком много перенаправлений» | проверьте `HTTPS_PUBLIC_PORT=443` в `/etc/rss-reader.env` (если HAProxy слушает 443) |
| служба падает при старте | `journalctl -u rss-reader -n 30`; частая причина — нет прав на каталог данных |
| вход невозможен: все администраторы отключены | перезапустите службу — при старте она включит первого администратора обратно |

## Установка без HAProxy (nginx или напрямую)

```bash
sudo ./deploy/install.sh                 # код в /opt/rss-reader, данные в /var/lib/rss-reader
journalctl -u rss-reader -f              # логи
```

Этот вариант ставит только службу на `127.0.0.1:8787` — TLS в этом случае

и перезапускает сервис, данные не трогает.

Переменные окружения: `PORT`, `HOST`, `DATA_DIR`, `REFRESH_MINUTES`, `ADMIN_USER`, `ADMIN_PASS`,
`HTTPS_PORT`, `HTTPS_PUBLIC_PORT`, `TLS_CERT`, `TLS_KEY`, `ACME_DIR`,
`FETCH_FULL=0`, `MAX_UNREAD_PER_FEED`, `KEEP_READ_DAYS`, `FULLTEXT_DELAY_MS`.

## Что нового: свежие изменения

Ниже — то, что появилось и поменялось в последних версиях, с поведением и деталями реализации.

### Три режима показа

Вместо двух режимов теперь три, и они выбираются **списком** — и в шапке, и в настройках
(«Режим по умолчанию»):

| Режим | Что показывает |
|---|---|
| `compact` | заголовок, подпись, несколько строк текста — без картинки |
| `compact-thumb` | то же, но слева миниатюра, текст её обтекает (**по умолчанию**) |
| `full` | статья раскрыта целиком |

* значение хранится у ленты (`feed.view`) либо берётся из `settings.defaultView`;
* при первом запуске новой версии старые значения `compact` переводятся в `compact-thumb`
  (флаг `settings.viewModeMigrated`), иначе у всех «исчезли» бы картинки в списке;
* на сервере принимаются все три значения (`POST /api/feeds/view`, `POST /api/settings`).

### Крупнее шрифты на телефоне

«Телефон» определяется не шириной окна, а **сенсорным экраном** (`pointer: coarse`), поэтому
раскладные устройства получают крупные шрифты и в сложенном, и в разложенном виде.

Выбранный размер применяется на ступень крупнее — отдельные шкалы у дерева и у текста:

| Шкала | Обычно | На телефоне |
|---|---|---|
| дерево подписок | 12 / 13 / 16,5 / 20 | 14 / 14,5 / **20** / 24 |
| текст статьи и краткий вид | 13 / 14,5 / 18 / 22 | 14,5 / **18** / 22 / 26 |

От размера дерева считается `--ui-scale` (масштаб интерфейса), поэтому кнопки и шапка тоже
подрастают. Межстрочный интервал (`data-line`) действует на заголовки и комментарии, а не только
на текст; краткий вид использует **тот же** интервал 1,65, что и полный (раньше расходились).

Старые сохранённые размеры краткого вида (11,5/12,5/16/19,5) при загрузке переводятся в новую
сетку, иначе в списке показывался один пункт, а рисовался другой размер.

### Меню «⋯» в шапке на телефоне

В строке статуса остаются только название, счётчик обновления, «обновить» и «⋯».
Кнопка темы скрыта на сенсорных экранах и переехала в меню, которое выглядит как панель:

* **Тема** — «Светлая» / «Тёмная» / «Авто» (последняя уважает системную настройку);
* **Какие статьи** — «Непрочитанные» / «Все»;
* **Как показывать статьи** — три режима показа;
* **Строк в кратком виде** — 1, 2, 3, 4, 6, 10;
* **Ещё** — «Обновить ленту», «Настройки».

Значения в меню всегда подставляются текущие (те же, что в шапке), меню закрывается кликом вне,
по Escape и после действия.

### Кнопки в карточке статьи

Кнопки действий (звёздочка, «прочитано», обновление, «следующая», поделиться) на сенсорных экранах
крупнее: 40×36 px, иконки 17 px, промежутки 6 px. Чтобы столбик кнопок не выходил за карточку,
у краткой карточки на телефоне `min-height: 132px`, а справа зарезервировано 54 px.

Плавающие кнопки у открытой статьи остаются полупрозрачными (50 %), проявляются при наведении
и **после остановки прокрутки** на сенсорных экранах (`.floating.settled`).

### Изображения и видео в статье

* картинки и видео идут через прокси `/api/img` и `/api/video` — это снимает запрет хотлинков,
  проверку референта и смешанное содержимое; если прокси не смог, ошибка не «съедает» картинку;
* под ещё не загруженную **одиночную** картинку резервируется место (3:2, минимум 120 px),
  поэтому текст не прыгает; в ряду место держит сам ряд (`min-height: 180px`, пока грузится);
* подряд идущие картинки собираются в блок `.img-row` — сетка сама решает, сколько влезет
  по ширине (на телефоне одна, на широком экране 2–4), высота ряда — по самой высокой картинке;
* видео из данных страницы (`video_url: …mp4`) добавляется плеером, если такого адреса нет в тексте.

### Разбор статьи: что вырезается

* служебные рубрики вместе с их содержимым: «Сейчас на главной», «Сейчас читают», «Читайте также»,
  «Новости по теме», «Вам может понравиться» и подобные — вместе с сеткой карточек под ними
  (считается вложенность `<div>`, поэтому статья и её картинки не задеваются);
* блоки-картинки в `<div>` превращаются в `<figure>` **на своём месте**, иначе картинки
  иначе картинки сваливались бы в конец статьи;
* краткий текст хранится до **1500** символов (было 400), этого хватает на все варианты «Строк»;
* при изменении разбора поднимаются `PARSER_VERSION` (перечитывание лент) и `BODY_VERSION`
  (перекачка сохранённых текстов): устаревшее тело считается отсутствующим, отметка `hasFull`
  снимается, и очередь докачки подтягивает текст заново.

### Фильтры работают на сервере

Раньше фильтры ленты применялись только в браузере: сервер хранил всё, и Fever показывал статьи,
скрытые в интерфейсе. Теперь:

* при приёме ленты отфильтрованные статьи **не сохраняются** (ни метаданные, ни текст, ни картинки);
* при сохранении фильтров и при каждом старте сервер вычищает уже накопленное — вместе с отметками
  «прочитано»/«избранное» и файлами текстов;
* Fever и `/api/data` отдают ровно то, что осталось в базе.

Логика та же, что была в клиенте: «скрывать» важнее «показывать только»; у Telegram заголовок
(имя канала) в поиск не входит. Снятие фильтра не возвращает удалённое — только то, что снова
придёт в обновлениях ленты.

### Комментарии: Хабр, Mobile-Review, iXBT и ixbt.games

* **Mobile-Review** — виджет Tolstoy Comments (`/api/chatpage/first?siteid=4388&url=…`): честный
  счётчик и ветки комментариев;
* **iXBT** и **ixbt.games** — `/api/comments?target_id=…&target_type=…`: номер и тип публикации
  берутся из JSON страницы (`publication_id`, `publication_type`), поэтому работают оба домена
  (`ixbt_article_announce` и `universal_publication`);
* **Хабр** — `kek/v2` как раньше.

Счётчики обновляются только для непрочитанного и избранного; сами комментарии качаются по кнопке.

### Подписка: живой поиск

Окно «Новая подписка» ищет по мере ввода (задержка 450 мс) и показывает найденные ленты строками:
название, подсказки (формат, число статей, «уже подписаны»), домен. Первый свободный вариант
выделен, повторный клик по строке подписывает. После добавления список **не пропадает**:
добавленная помечается как подписанная, выделение уходит на следующую — так с одного сайта можно
подписаться на несколько лент сразу.

Каналы Telegram ищутся и по ссылкам самого сайта (`t.me/…`), а не только по RSS-автообнаружению.

### PWA: кэш и прогрев

`sw.js` держит три кэша:

| Кэш | Что | Стратегия |
|---|---|---|
| `rss-shell-*` | страница, стили, скрипт, шрифты, иконки | из кэша сразу, обновление в фоне |
| `rss-data-*` | `/api/data`, `/api/bodies` | сначала кэш, потом свежее |
| `rss-media-*` | `/api/img`, `/api/thumb`, `/api/video` | из кэша навсегда |

Если ни кэша, ни сети нет, отдаётся **ошибка сети**, а не пустой JSON: раньше клиент принимал «{}»
за данные и падал на `state.data.items is not iterable`. Клиент дополнительно проверяет ответ
(в нём обязаны быть массивы `items` и `feeds`) и не подменяет состояние «битым».

Раз в час клиент прогревает кэш: просит сервер докачать полные тексты (`POST /api/queue`),
забирает тела первых 30 статей через `/api/bodies` и просит service worker обновить `/api/data`.
В закрытом браузере прогрев не идёт — фоновой загрузки там нет.

### Отметки о прочтении без сети

Отметка ставится **сразу локально**, попадает в очередь (`localStorage.rss.pendingRead`) и
накладывается поверх приходящих с сервера данных, поэтому старый кэш не «возвращает» статью в
непрочитанные. Отправка — при появлении сети, после удачного опроса и при следующем действии;
ошибок и тостов при этом нет.

### Фоновые задачи встают на паузу при прокрутке

Пока список прокручивается (`state.scrolling`), не запускаются: перерисовка списка, догрузка тел
статей, двухминутный опрос, опрос очереди докачки, обновление времени, прогрев кэша. Всё
отложенное выполняется через 220 мс после остановки (`flushScrollWork()`).

Отдельно: **пока играет видео**, список не перерисовывается вообще — перерисовка откладывается до
паузы, иначе плеер схлопывался обратно в кнопку «проиграть». Повторы загрузки тел ограничены тремя
попытками (раньше шли каждые 3 секунды и вызывали мерцание рамки).

### Публикация в GitHub одной командой

`tools/publish.ps1` собирает чистую копию проекта в `%TEMP%\MakRSS` (без `data/`, `rus-host.txt`,
OPML, `preview/`), проверяет, что в копию не попали доступы, и отправляет в репозиторий:

```powershell
.\tools\publish.ps1                      # собрать и отправить
.\tools\publish.ps1 -Message "фикс X"    # своё сообщение коммита
.\tools\publish.ps1 -DryRun              # только показать изменения
```

Рабочая папка при этом остаётся без git-репозитория (она внутри другого репозитория и
синхронизируется ownCloud); файлы, которые есть только в репозитории (`LICENSE`), скрипт
возвращает из git после зеркалирования.

## Трафик: как читалка экономит мегабайты

Замеры делаются в реальном браузере через CDP (`tools/cdp-traffic.mjs`) на тестовом
пользователе, а серверный учёт байтов по маршрутам лежит в `lib/traffic.mjs`
(снимок — `<данные>/traffic.json`).

Что было и что стало:

| Что | Было | Стало |
|---|---|---|
| Список статей (`/api/data`) | 2,05 МБ gzip | 934 КБ brotli |
| Список по виду, 40 карточек | — | 33 КБ |
| Отметка «прочитано» | 7,04 МБ | 23 байта |
| Избранное | полный список | 11 байт |
| Сессия «вход + 12 прокруток» в браузере (из кэша SW) | ~10 МБ и больше | **220 КБ** |
| Та же сессия, реально отдано сервером | 13,8 МБ | **1,15 МБ** |
| Миниатюра карточки | 178 КБ | **6 КБ** |
| Иконка подписки | ~100 КБ | **3 КБ** |

Ключевые решения:

* список статей отдаётся **постранично по виду** (`/api/data?view=feed:<id>&limit=40&offset=0`);
* отметки `/api/read` и `/api/star` не возвращают состояние целиком (`light: true`);
* анонс в списке — 180 символов, пустые поля не отправляются;
* миниатюры карточек идут через `/api/thumb`, крупные картинки пережимаются в WebP;
* фоновых прогревов нет: тексты загружаются только по клику;
* неудачные фавиконы кэшируются в service worker и повторно не запрашиваются.
