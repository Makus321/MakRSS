# Аудит CSS проекта MAK RSS Reader

**Дата проверки:** 2026-11-25  
**Проверенные файлы:**
- `public/style.css` (1503 строки)
- `public/index.html` (593 строки)
- `public/admin.html` (119 строк, встроенный `<style>`)
- `public/app.js` (проверка фактического использования классов и CSS-переменных)

---

## Краткое резюме

Стили проекта хорошо решают прикладные задачи (темизация, 18 цветовых палитр, масштабирование интерфейса, адаптация под мобильные устройства и iOS PWA). Однако `public/style.css` заметно разросся в режиме «дописывания в конец» (append-only): в файле накопилось много дублирующихся правил, конфликтующих медиа-запросов, неиспользуемых переменных и мелких багов контраста/каскада.

Рефакторинг и очистка позволят сократить объём `public/style.css` примерно на **25–35%**, устранить скрытые конфликты стилей на планшетах и мобильных устройствах, а также улучшить доступность и поддерживаемость.

## 1. Критические и функциональные проблемы

### 1.1. Низкий контраст кнопок `.btn.primary` в светлых палитрах
- **Где:** `public/style.css:61`, `public/style.css:83-92`, `public/style.css:541`
- **Проблема:** В `:root[data-theme="light"]` задано `--accent-contrast: #1b1206;` (тёмно-коричневый текст). При этом в светлых палитрах `sky` (`#2563eb`), `mint` (`#15803d`), `lavender` (`#7c3aed`), `blush` (`#db2777`), `ice` (`#0e7490`) акцентный цвет достаточно тёмный. Тёмный текст на тёмно-синем или тёмно-зелёном фоне практически нечитаем (не проходит WCAG AA). Белый контраст (`#ffffff`) переопределён только для палитры `mono` (строка 92).
- **Рекомендация:** Для всех светлых палитр с насыщенным тёмным акцентом задать `--accent-contrast: #ffffff;`.

### 1.2. Конфликт брейкпоинтов `700px` и `900px` для карточек с превью
- **Где:** `public/style.css:823-896` и `public/style.css:1314-1331`
- **Проблема:** В `@media (max-width: 900px), (pointer: coarse)` (строки 888–892) для карточек задаётся блочная раскладка с обтеканием (`.a-head { display: block; }`, `.a-thumb { float: left; }`). Но ниже в файле идёт `@media (min-width: 700px)` (строка 1314), который перебивает `.article.has-thumb .a-head` обратно на `display: flex`. В диапазоне ширин **700–900px** (а также на планшетах с `pointer: coarse` и шириной ≥ 700px) правила смешиваются: `display: flex` сочетается с мобильными отступами и `float: left`.
- **Рекомендация:** Выровнять брейкпоинты (например, единая граница мобильной/десктопной раскладки или явное разделение `min-width: 901px` / `max-width: 900px`) и не смешивать `float` с `flex`.

### 1.3. Сломанный нижний отступ списка в режиме «Свободно» на мобильных
- **Где:** `public/style.css:873`, `public/style.css:904`, `public/style.css:1215` vs `public/style.css:1274`
- **Проблема:** Для `.list` на мобильных специально задан запас снизу `calc(100dvh + 60px)` (чтобы последнюю статью можно было прокрутить выше середины экрана для отметки прочтения). Но для `.list.comfortable` в строке 1274 задано `padding: 6px 2px 70vh;` — используется `70vh` вместо `calc(100dvh + 60px)`.
- **Рекомендация:** Заменить `70vh` на `calc(100dvh + 60px)` (или не переопределять `padding-bottom`, а менять только `padding-top`).

### 1.4. Противоречие в размере шрифта режима `.list.comfortable`
- **Где:** `public/style.css:555` и `public/style.css:1271`
- **Проблема:** В строке 555 задано `.list.comfortable .a-body { font-size: calc(var(--font-article) * 1.03); }`, но в строке 1271 то же правило перезаписывается на `font-size: var(--font-article);`. Строка 555 полностью мертва.
- **Рекомендация:** Удалить строку 555 и её устаревший комментарий.

### 1.5. Конфликт `z-index` между слоями интерфейса
- **Где:** по всему `public/style.css`
- **Проблема:** Значения `z-index` разбросаны бессистемно (`1, 2, 3, 5, 20, 40, 45, 50, 60, 80, 90`). Есть прямые коллизии:
  - `.new-row` (`z-index: 45`, строка 496) и `.sidebar` на мобильных (`z-index: 45`, строка 828) — при открытом меню плашка новых статей может перекрывать сайдбар.
  - `.head-menu` (`z-index: 60`, строка 1123; ранее было `40` в строке 1010) и `.toast` (`z-index: 60`, строка 805) — одинаковый слой.
- **Рекомендация:** Вынести шкалу слоёв в CSS-переменные в `:root`:
  ```css
  --z-sticky: 10;
  --z-backdrop: 40;
  --z-sidebar: 45;
  --z-floating: 48;
  --z-modal: 50;
  --z-menu: 55;
  --z-toast: 60;
  --z-loader: 80;
  --z-lightbox: 90;
  ```

## 3. Разрозненные медиа-запросы (`@media`)

В `public/style.css` медиа-запросы повторяются многократно с одинаковыми условиями:
- `@media (max-width: 900px)` — **5 раз** (строки `810`, `823`, `1210`, `1214`, `1273`).
- `@media (max-width: 560px)` — **5 раз** (строки `917`, `1030`, `1128`, `1139`, `1468`).
- `@media (pointer: coarse)` — **4 раза** (строки `823`, `934`, `1045`, `1116` — причём `1045` и `1116` дублируют `#theme-toggle` и `#tune-btn`).
- `@media (max-width: 699px)` — **2 раза** (строки `1299`, `1334`).

**Рекомендация:** Сгруппировать адаптивные правила в единые блоки по брейкпоинтам в конце файла (или рядом с соответствующими компонентами, если файл будет разбит на модули). Это сразу уберёт дубли вроде `.a-head { padding-right: 50px }` (встречается 4 раза) и `.list { padding: 2px 2px calc(100dvh + 60px) }` (встречается 3 раза).

## 4. CSS-переменные и токены

### 4.1. Неиспользуемые переменные
- `--panel-palette` объявляется **20 раз** (в `:root`, `:root[data-theme="light"]` и во всех 18 палитрах, строки `25, 50, 72-92`), но **ни разу не используется** (в строках `109` и `111` используется `--bg-palette`).
- `--actions-stop` (строка `636`), `--actions-min` (строка `1209`), `--badge-text` (строка `1257`) читаются через `var(...)`, но нигде в CSS или `app.js` не устанавливаются — работают только их значения по умолчанию.

### 4.2. Избыточное дублирование в палитрах
- В строках `72–92` каждая палитра задаёт `--bg` и `--bg-palette` одним и тем же цветом, хотя в строках `108–111` `--bg` и `--panel` всё равно вычисляются через `var(--bg-palette)` и `var(--neutral)`.

### 4.3. Хардкод цветов
- Цвет ошибки `#e5573f` захардкожен **6 раз** (строки `349, 474, 803, 806, 1354, 1370`), цвет успеха `#4a9c62` — в строке `1353`.
- **Рекомендация:** Вынести в токены `--danger` и `--ok` (как это уже сделано в `public/admin.html:8-9`), с адаптацией под светлую и тёмную темы.

## 5. Типографика и шрифты

### 5.1. Повторяющиеся `calc(Npx * var(--ui-scale, 1))`
- Конструкция `font-size: calc(... * var(--ui-scale, 1))` встречается в `style.css` **более 45 раз**.
- При этом в 4 местах про неё забыли и оставили жёсткие пиксели:
  - `.feed-row .row-tag` (`10px`, строка `442`)
  - `#sidebar-version` (`10px`, строка `1373`)
  - `.settings-build` (`11px`, строка `1502`)
  - `.lightbox-share` (`19px`, строка `1450`)
- **Рекомендация:** Задать базовый `font-size: calc(14px * var(--ui-scale, 1))` на `html` и использовать `rem` (или шкалу токенов `--fs-xs`, `--fs-sm`, `--fs-base`, `--fs-lg`), тогда масштабирование будет работать автоматически и единообразно для всего UI.

### 5.2. Неполные начертания `@font-face` и лишние файлы шрифтов
- В `public/fonts/` лежат 4 файла `charter_*.woff2` (`charter_regular.woff2`, `charter_bold.woff2`, `charter_italic.woff2`, `charter_bold_italic.woff2`), которые **не подключены** в `style.css` (вместо них используются `xcharter-*.woff2`). Если они больше не нужны — их можно удалить.
- У шрифтов `"Читалка Мягкая"` и `"Читалка Тонкая"` подключено только начертание `font-weight: 300` (нет `700`), поэтому жирный текст синтезируется браузером (faux bold). У `"Читалка Удобная"` курсив подключён только для латиницы (`charis-latin-400-italic.woff2`).

## 6. Проблемы каскада, `!important` и режима `body.no-borders`

### 6.1. Избыточный `!important`
- Строки `1150–1154`: `.a-excerpt` использует `!important` для `-webkit-line-clamp`, хотя в `public/app.js:1704` те же свойства всё равно проставляются инлайн в `style="..."`. Лучше убрать инлайн-стили из `app.js` (оставив только `--excerpt-lines`) и убрать `!important` из CSS.
- Строки `1216–1220`: `.article { max-width: 100% !important; width: 100% !important; ... }` — `!important` не нужен, так как в `app.js` задаётся переменная `--read-width`, а не `max-width`. Достаточно задать `--read-width: 100%` или обычное правило ниже по каскаду.

### 6.2. Неполная работа `body.no-borders`
- **Где:** `public/style.css:377-394`
- **Проблема:**
  1. В списке селекторов присутствует `.card` (строка `378`), которого нет в `index.html` (он есть только в `admin.html`, который не подключает `style.css`).
  2. Правило стоит в начале файла (строка `377`), поэтому его перебивают более поздние/специфичные правила с рамками: `.flag.comment-chip` (`588`), `#settings-close` (`780`), `.modal-head .head-actions .btn` (`1168, 1172`), `#prompt-modal #prompt-input` (`1495`).
- **Рекомендация:** Перенести блок `body.no-borders` в конец файла (или управлять им через переопределение токена `--line: transparent;` на `body.no-borders` — это автоматически уберёт 90% рамок без длинного списка селекторов).

## 7. Доступность (a11y) и UX

1. **Потеря индикатора фокуса с клавиатуры:**
   - `select:focus-visible { outline: none; }` (строка `538`) и `outline: none` на полях ввода (`.search`, `.row-line input`, `#prompt-input`). В режиме `body.no-borders` или при слабом контрасте рамки пользователь с клавиатуры не видит, какой элемент в фокусе.
   - У `.btn`, `.icon-btn`, `.nav-item`, `.row` нет явного `:focus-visible`.
   - **Рекомендация:** Добавить единый `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }` для интерактивных элементов.
2. **Неполная поддержка `prefers-reduced-motion`:**
   - В строке `1415` замедляется только `.app-spinner`, но не учитываются `.icon-btn.spin, .btn.spin` и `transition` (`.sidebar`, `.article`, `.a-actions`).
3. **Использование `100vh` в лайтбоксе:**
   - В `.lightbox img` (`public/style.css:1439`) указано `max-height: calc(100vh - 24px)`. На мобильных браузерах с динамической адресной строкой лучше использовать `100dvh` (с фоллбэком `100vh`).
4. **Фоллбэк для `color-mix()`:**
   - В `.comment.is-new` (`public/style.css:723`) используется `background: color-mix(in srgb, var(--accent) 8%, transparent);`. Для старых WebView стоит добавить строкой выше `background: var(--accent-soft);`.

## 8. Встроенные стили в `public/admin.html`

- **Где:** `public/admin.html:7-48`, `65`, `70`, `97-105`
- **Проблемы:**
  1. Все стили админки (`.btn`, `.badge`, `input`, `select`, цветовые токены) написаны инлайн в `<style>` и дублируют базовые компоненты `style.css`.
  2. Есть инлайн-атрибуты `style="..."` в HTML (`style="grid-template-columns:1fr"` на строке 65 и `style="font-size:12.5px"` на строке 70).
  3. Таблица пользователей (`<table>`, строки `97–105`) с 9 колонками не имеет обёртки с `overflow-x: auto` — на узких экранах страница будет вылезать за пределы viewport.
  4. Отсутствует адаптация под мобильные экраны (`@media`) и стили `:focus-visible`.
- **Рекомендация:** Обернуть таблицу в `.table-wrap { overflow-x: auto; }`, убрать инлайн-стили, добавить базовый `@media (max-width: 640px)` для `header` и `.wrap`.
